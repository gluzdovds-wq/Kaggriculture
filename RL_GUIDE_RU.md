# Kaggriculture локально и простой RL — понятное введение

Этот файл объясняет четыре вещи: как запустить игру, как устроен агент, как
увидеть результат и как написать первый учебный RL-алгоритм. Для реального
соревновательного агента одной простой RL-модели недостаточно: пространство
действий очень большое, награда приходит только в конце 720 ходов, а ошибки в
логистике часто важнее выбора модели.

## 1. Как запустить игру

В проекте используется отдельное Python-окружение с официальным движком
`kaggle-environments==1.32.7`:

```powershell
cd C:\Users\Dmitry\Desktop\Kaggle\Kaggriculture
C:\Users\Dmitry\.venvs\kg\Scripts\python.exe evaluate.py --opponent starter --games 2
```

`--games 2` означает два seed, причём каждый будет сыгран с обеих сторон. Это
важно: один и тот же агент иногда получает разный результат на местах 0 и 1.

Для проверки против файла другого агента:

```powershell
C:\Users\Dmitry\.venvs\kg\Scripts\python.exe evaluate.py `
  --opponent C:\path\to\other_agent\main.py --games 2
```

Для строгой парной арены, хэшей и времени действий:

```powershell
C:\Users\Dmitry\.venvs\kg\Scripts\python.exe arena.py `
  --opponent starter --seeds 4 --output artifacts\arena\run.json
```

Главная локальная метрика — доля побед в одинаковых seed с обеих сторон.
Количество денег полезно для диагностики, но на Kaggle победа с перевесом в
одну монету и победа с перевесом в сто тысяч дают одинаковый исход матча.

## 2. Как устроен агент

Kaggle вызывает функцию `agent(obs)` один раз на каждом ходу. `obs` — это
наблюдение: день и час, обе видимые фермы, рынок, город и наша приватная часть
(семена, амбар, инвентари работников).

Функция возвращает словарь:

```python
def agent(obs):
    return {
        "farmer": ["WATER"],
        "hands": [["NORTH"], ["HARVEST"]],
        "market": [["SELL", "CARROT", 5]],
    }
```

- `farmer` — одно действие основного фермера;
- `hands` — по одному действию каждого нанятого работника;
- `market` — до десяти приказов рынку.

Движок молча превращает недопустимые действия в `PASS`. Поэтому сильный агент
должен не только выбирать выгодные действия, но и резервировать семена,
проверять клетки, учитывать порядок работников и успевать продать товары до
конца сезона.

## 3. Как наблюдать результат

Самый короткий вариант в Python:

```python
from kaggle_environments import make

env = make("kaggriculture", configuration={"seed": 42}, debug=False)
env.run(["main.py", "starter"])
print([(state.status, state.reward) for state in env.steps[-1]])
print(env.render(mode="ansi"))
```

`env.steps` хранит всю траекторию. В каждом состоянии можно посмотреть:

- `state.action` — что приказал агент;
- `state.observation.farms` — видимые фермы и деньги;
- `state.observation.market` — цены и запасы рынка;
- `state.observation.private` — наш амбар, семена и инвентари;
- `state.status` и `state.reward` — завершение и финальный банк.

Чтобы сохранить replay, запустите `evaluate.py` с параметром:

```powershell
--replay-dir artifacts\replays
```

Replay нужен не только для красивой картинки. По нему ищут причинную цепочку:
какое действие не выполнилось, почему растение не полили, где работник потерял
ход, когда переполнился амбар и сколько товара осталось непроданным.

## 4. Что такое RL простыми словами

Reinforcement learning — обучение через последствия действий.

1. Агент видит состояние `s`.
2. Выбирает действие `a`.
3. Среда переходит в новое состояние и когда-нибудь возвращает награду `r`.
4. Агент повышает оценку действий, после которых результат был хорошим, и
   понижает оценку неудачных.

В табличном Q-learning хранится число `Q(s, a)` — ожидаемая будущая награда,
если в состоянии `s` выбрать действие `a`. Простое обновление:

```text
Q(s,a) ← Q(s,a) + α × (r + γ × max Q(s',·) − Q(s,a))
```

`α` задаёт скорость обучения, `γ` — насколько ценится далёкое будущее.
Стратегия epsilon-greedy обычно выбирает лучшее известное действие, но с
вероятностью `epsilon` пробует случайное. Без исследования агент никогда не
узнает, что неизвестный вариант мог быть лучше.

## 5. Первый реально запускаемый RL-пример

В `rl/train_bandit.py` используется самый простой честный вариант: состояние
одно — начало сезона, а RL-действие — выбор целой макрополитики, например
`carrot-h5` или `wheat-h3`. После полного матча награда равна `1` за победу,
`0.5` за ничью и `0` за поражение.

Запуск короткой учебной серии:

```powershell
C:\Users\Dmitry\.venvs\kg\Scripts\python.exe rl\train_bandit.py `
  --episodes 6 --opponent starter
```

После каждой партии программа печатает выбранную политику, награду и новую
оценку `Q`. Полная история сохраняется в `artifacts/rl_bandit.json`.

Это уже RL: выбор влияет на всю траекторию, терминальная награда меняет Q, а
epsilon-greedy балансирует использование и исследование. Но это ещё не сильный
Kaggle-агент, потому что он выбирает стратегию только один раз за сезон.

## 6. Как перейти к более серьёзному RL

Разумный путь для Kaggriculture:

1. Сначала сделать точный rules-based planner и локальную paired arena.
2. Сжать огромное действие до понятных macro-actions: «расширить землю»,
   «посадить пакет», «обслужить животных», «продать после town tick».
3. Ввести legal masks, чтобы модель не выбирала невозможные команды.
4. Начать с imitation learning: модель учится повторять хорошие действия
   planner-а на доступных при inference признаках.
5. Затем дообучать PPO/self-play на награде win/loss, сохраняя исторических
   соперников, чтобы политика не забывала старые контрстратегии.
6. Всегда сравнивать новый вариант на untouched seed, с обеих сторон и против
   нескольких разных стилей, а не только против своей копии.

Хорошая RL-модель здесь не заменяет правила. Она ранжирует допустимые планы или
выбирает макростратегию, а точный исполнитель гарантирует полив, логистику,
лимиты рынка, терминальную продажу и безопасный fallback.
